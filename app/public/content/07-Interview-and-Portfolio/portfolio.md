# 🎨 Xây Dựng Portfolio Unity

[⬅️ Interview Index](./README.md)

> Portfolio là tài sản nghề nghiệp quan trọng nhất của bạn. Bắt đầu xây từ Junior, nâng cấp suốt sự nghiệp.

---

## 1. Portfolio gồm những gì?

```
┌─────────────────────────────────────────────┐
│  1. Game/dự án chơi được (quan trọng nhất)   │
│  2. Source code trên GitHub (sạch, có README)│
│  3. Video gameplay / demo reel               │
│  4. Devlog / technical blog (cách bạn tư duy)│
│  5. CV/résumé gọn + LinkedIn                 │
│  6. (Tùy) trang web portfolio cá nhân        │
└─────────────────────────────────────────────┘
```

---

## 2. Dự án trong portfolio — chất lượng

> 🎯 **2-3 dự án XUẤT SẮC > 10 dự án nửa vời.** Nhà tuyển dụng xem kỹ 1-2 cái đầu.

**Một dự án portfolio tốt:**
- ✅ **Chơi được** (build/WebGL link, không bắt họ tự build).
- ✅ **Hoàn chỉnh** (có start/play/end, polish, không lỗi).
- ✅ **Thể hiện kỹ năng cụ thể** (kiến trúc? chuyên môn? game feel?).
- ✅ **Code sạch** trên GitHub với README chuyên nghiệp.
- ✅ **Kể được câu chuyện kỹ thuật** ("tôi giải quyết vấn đề X thế nào").

**Nên có (theo hướng):**
- Một dự án thể hiện **kiến trúc tốt** (Mid+).
- Một dự án thể hiện **chuyên môn sâu** (mảng bạn chọn).
- (Bonus) đóng góp **open-source** hoặc **tool/asset** chia sẻ.

---

## 3. README cho dự án (nhà tuyển dụng đọc cái này)

Một README tốt gồm:
```markdown
# Tên Game
GIF gameplay ngay đầu (gây ấn tượng 3 giây)

## Mô tả
Game gì, thể loại, làm trong bao lâu, một mình/nhóm.

## Điểm kỹ thuật nổi bật
- Kiến trúc: dùng ScriptableObject event system để...
- Tối ưu: object pooling giảm GC từ X xuống Y
- [Những quyết định kỹ thuật đáng kể]

## Cách chơi / Build
Link chơi (WebGL/itch) + hướng dẫn build.

## Công nghệ
Unity version, packages, pattern dùng.
```

> 💡 Phần "Điểm kỹ thuật nổi bật" là cái phân biệt bạn. Cho thấy **bạn tư duy như engineer**, không chỉ "làm theo tutorial".

---

## 4. GitHub sạch

- Code có cấu trúc, đặt tên tốt, comment hợp lý (thể hiện clean code).
- `.gitignore` đúng (không commit `Library/`).
- Commit history rõ ràng (không chỉ 1 commit "final").
- README tốt cho mỗi repo đáng khoe.
- Pin các repo tốt nhất trên profile.

---

## 5. Demo reel / Video

- **Video gameplay** ngắn cho mỗi dự án (30-60s, hook nhanh).
- **(Senior/specialist) Demo reel:** tổng hợp các kỹ thuật/effect/system bạn làm.
- Đăng YouTube/Vimeo, nhúng vào portfolio.

---

## 6. Technical Blog / Devlog (đòn bẩy mạnh)

Viết về **cách bạn giải quyết vấn đề kỹ thuật**:
- "Cách tôi xây dựng ability system data-driven."
- "Tôi giảm frame time 40% như thế nào."
- "Bài học khi làm multiplayer đầu tiên."

**Lợi ích:**
- Chứng minh bạn **tư duy sâu**, không chỉ code chạy.
- SEO — nhà tuyển dụng tìm thấy bạn.
- Củng cố kiến thức (dạy = học).

> Nền tảng: dev.to, Medium, Hashnode, blog cá nhân, hoặc README chi tiết.

---

## 7. CV / Résumé cho game dev

- **Gọn 1 trang** (Junior/Mid), nêu bật **dự án + kỹ năng + impact** (có số liệu).
- Link portfolio/GitHub/itch nổi bật ngay đầu.
- Liệt kê: Unity, C#, pattern, hệ thống đã làm, công cụ.
- Mô tả dự án theo **kết quả** ("tối ưu giảm 40% draw call"), không chỉ "làm việc với Unity".
- LinkedIn cập nhật + active trong cộng đồng.

---

## 8. Portfolio theo level

| Level | Portfolio nên có |
|-------|------------------|
| **Junior** | 2-3 game hoàn chỉnh, GitHub sạch, video, 1 README ngon |
| **Mid** | + 1 dự án kiến trúc tốt (có sơ đồ), chuyên môn 1 mảng, vài bài blog, đóng góp OSS |
| **Senior** | + bằng chứng leadership, hệ thống lớn, game đã ship, talks/blog sâu, danh tiếng cộng đồng |

---

## 9. Lỗi portfolio thường gặp

- ❌ Nhiều dự án dở thay vì ít dự án ngon.
- ❌ Bắt nhà tuyển dụng tự build (không có link chơi).
- ❌ README trống/sơ sài.
- ❌ Chỉ show tutorial-following projects (ai cũng giống nhau).
- ❌ Không kể được câu chuyện kỹ thuật khi được hỏi.
- ❌ Commit "final final v2" lộn xộn.
