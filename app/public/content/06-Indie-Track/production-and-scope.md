# 📐 Production & Scope — Kỹ Năng Sống Còn Của Indie

[⬅️ Indie Index](./README.md)

> ⭐ **Đây là file quan trọng nhất của nhánh Indie.** Lý do #1 game indie thất bại không phải code dở — mà là **scope quá lớn → không bao giờ hoàn thành**.

---

## 1. Kẻ thù số 1: Scope Creep

> **Scope creep:** phạm vi game cứ phình to ("thêm tính năng này nữa", "thêm boss nữa", "thêm hệ thống nữa") cho đến khi game **không bao giờ xong**.

**Sự thật:**
- Game của bạn nên **nhỏ hơn 3 lần** so với bạn nghĩ ban đầu.
- Mọi tính năng tốn **nhiều thời gian hơn** bạn ước (polish, bug, edge case, tích hợp).
- "10% cuối" (polish, ship) tốn **gần bằng 90% đầu**.

---

## 2. Nguyên tắc Scope cho Indie

1. **🎯 Một game nhỏ HOÀN THÀNH > game lớn dang dở.** Luôn luôn.
2. **✂️ Cắt không thương tiếc.** Mỗi tính năng phải "đáng giá thời gian". Nghi ngờ → cắt.
3. **🧪 Vertical slice trước.** Làm 1 phần game hoàn chỉnh 100% (1 level polish đủ) trước khi nhân rộng.
4. **📦 MVP (Minimum Viable Product):** phiên bản nhỏ nhất mà vẫn vui & ship được.
5. **⏳ Buffer thời gian:** việc gì cũng nhân đôi ước lượng. Để dành thời gian cho bug & polish.

---

## 3. Cách định scope đúng

```
Hỏi mỗi tính năng:
  - Nó có phục vụ CORE LOOP không? (không → cắt)
  - Nó tốn bao lâu THẬT? (gồm polish, bug, tích hợp)
  - Cắt nó game có còn vui không? (còn → cắt được)
  - "Nice to have" hay "Must have"? (nice → để v2)
```

**Quy tắc thực tế:**
- Game đầu thương mại: chọn scope bạn nghĩ làm **3 tháng** → thực tế sẽ là **6-9 tháng**.
- Thà ra game nhỏ rồi update, hơn ôm game khổng lồ không ship.

---

## 4. Quy trình production của Indie

```
1. Prototype (find the fun)      → 1-2 tuần
2. Vertical slice (1 phần đẹp)   → vài tuần (chứng minh game khả thi)
3. Production (nhân content)     → phần lớn thời gian
4. Polish & juice                → nhiều hơn bạn nghĩ
5. Beta / playtest               → sửa dựa trên người chơi thật
6. Marketing (đã chạy từ đầu)    → xem marketing-and-release.md
7. Ship & post-launch            → update, fix, lắng nghe
```

---

## 5. Quản lý dự án cá nhân/nhóm nhỏ

- **Task board:** Trello / Notion / GitHub Projects — chia việc nhỏ, theo dõi.
- **Milestone:** đặt cột mốc (prototype xong, vertical slice xong, content complete, ship).
- **Devlog:** ghi lại tiến độ (vừa kỷ luật bản thân, vừa marketing — xem [marketing](./marketing-and-release.md)).
- **Định kỳ review:** mỗi tuần/tháng tự hỏi "có đang đi đúng hướng & đúng scope không?".

---

## 6. Tâm lý & kỷ luật (phần ít nói nhưng quan trọng)

- **Motivation dao động.** Kỷ luật & thói quen quan trọng hơn cảm hứng.
- **Burnout là thật.** Nghỉ ngơi, đừng crunch dài hạn.
- **"Second game syndrome":** game đầu thường nhỏ & xong; game sau dễ phình tham vọng → cẩn thận.
- **Hoàn thành tạo động lực.** Ship game nhỏ → tự tin → game sau tốt hơn.
- **So sánh giết chết niềm vui.** Đừng so game của bạn với studio 50 người.

---

## 7. Vì sao programmer hay sa lầy scope?

- Thích "hệ thống đẹp" → over-engineer cái người chơi không thấy.
- Thích thêm tính năng kỹ thuật thú vị → quên hỏi "có vui không / có cần không".
- Polish code thay vì polish game.

> 🎯 **Nhắc nhở:** Người chơi không thấy kiến trúc của bạn. Họ thấy game có vui & hoàn chỉnh không. Cân bằng "code đủ tốt" và "ship".

## 🎯 Thực hành

```
Junior:  Hoàn thành game jam (ép scope cực nhỏ) · tập "ship" thay vì "perfect"
Mid:     Ship 1 game nhỏ thương mại/itch · thực hành MVP & vertical slice · cắt scope thật
Senior:  Quản lý dự án nhiều tháng · milestone · điều phối nhóm nhỏ · post-launch
```
